Продолжение РР1 Макарова Анатолия Александровича. Исходный проект https://github.com/iONEimee/electronic-queue. Базовое состояние develop 408e1b8bba8036013b1a76cd841f2d5b3c7e37bb.

Сохранена ИСР 1.1 Анализ требований, 1.2 Проектирование архитектуры, 1.3 Разработка модуля талонов, 1.4 Разработка логики очереди, 1.5 Тестирование.

## Демонстрация

Из корня извлечённого пакета откройте `prototype/rr2/index.html` в современном браузере. Данные сохраняются только в текущем браузере. Для исходного примера нажмите «Восстановить пример». Покажите выдачу талона, вызов к окну, начало и завершение обслуживания, табло и статистику. Окно 1 обслуживает A, окно 2 — B и C. Неявка доступна через две минуты после вызова. Приостановление услуги закрывает только новую выдачу.

Рекомендуется одна вкладка для воспроизводимой демонстрации. Обновление между вкладками реализовано событием storage, но параллельная запись в localStorage не обеспечивает серверные транзакции. Не используйте прототип для реального потока посетителей. В нём отсутствуют авторизация, сетевой API, БД и печать.

## Проверка и дальнейшая реализация

Проведена 21 сценарная проверка локального интерфейса. Полный сервер, блокировки PostgreSQL, идемпотентность HTTP, безопасность ролей, нагрузка и восстановление ещё не реализованы и не проверены. SQL и OpenAPI — проектные спецификации, а не действующее приложение.

Для реализации сохраняются Python, TicketGenerator, QueueManager, Ticket и Service. Технические решения расширяют исходные заготовки. Не переносить в рабочую реализацию неопределённый Base и прежний некорректный импорт теста из features.queue_manager. Исходная модель number Integer должна стать строковой. Состояния и ограничения брать из текущей спецификации.

Проект предназначен для размещения в `docs/rr2` и `prototype/rr2` исходного репозитория. Наличие этих файлов в локальном архиве само по себе не подтверждает публикацию.
