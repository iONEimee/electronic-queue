# Проверка проекта и приёмка реализации

База критериев — F01–F10, N01–N08 и раздел 4.3 отчёта. Проверки T01–T12 являются планом серверной приёмки и не заявлены выполненными.

Для интеграционных проверок нужен изолированный PostgreSQL со схемой соответствующей версии и сервер API. Для конкурентного вызова запускаются два запроса к одной услуге и разным окнам; ожидаются разные UUID и соблюдение FIFO. Для одного окна параллельные вызовы должны завершиться одним активным талоном и конфликтом второго запроса. Для выдачи повторяются одинаковый ключ и тело; при несовпадении тела ожидается 409. При имитации ошибки между UPDATE и INSERT event вся транзакция откатывается.

Граничные случаи: отсутствие услуг, закрытая выдача, пустая очередь, последний талон, 119 и 120 секунд ожидания, конец московских суток, пустая статистика и повтор команды после сетевого сбоя. Для проверки даты время задаётся контролируемыми часами тестового стенда. Восстановление копии выполняется на отдельной БД, с фиксацией фактического времени и контрольных записей. Не подменять проверку восстановления успешным созданием файла копии.

Нагрузочная проверка измеряет реальные запросы при 30 сессиях и до 10 окон, целевой P95 не более 2 секунд. Табло оценивается от COMMIT до появления номера, не более 3 секунд. Доступность оценивается мониторингом в объявленные часы работы. Непроверенные значения остаются целями, а не результатами.

## Фактически проверенный локальный прототип

21 проверка: наличие пяти экранов; выдача UUID, номера и времени; последовательные номера; отмена waiting; блокировка закрытой выдачи; обслуживание старого талона при закрытой выдаче; блокировка второго вызова занятого окна; сохранение called при повторе; запрет ранней неявки; начало обслуживания; завершение с освобождением окна; FIFO услуг окна; переход к другой допустимой услуге; неявка после двух минут; пустая очередь; сохранение после перезагрузки; отсутствие NaN в метриках; содержание CSV; экранирование разметки в названии; отсутствие горизонтального выхода экрана выдачи при 390 px; отсутствие ошибок JavaScript.

Проверки выполнены автоматически в Microsoft Edge с помощью Playwright. Граница двух минут проверена контролируемым изменением демонстрационного времени вызова; реальный двухминутный цикл ожидания не засекался. Для снимков пяти экранов использован исходный демонстрационный набор данных.

Результат не подтверждает серверную авторизацию, целостность PostgreSQL, HTTP идемпотентность, производительность, отказоустойчивость или безопасность промышленной системы.

## Условия выпуска

Все обязательные сценарии проходят на целевой среде; нет критических дефектов доступа, потери истории и двойного вызова. Для каждой записи протокола фиксируются версия, среда, входные данные, ожидаемый/фактический результат, статус и дефект. Содержимое ТЗ, диаграмм, DDL и API проверяется одной версией. В публичном исходном репозитории фактически доступны docs/rr2 и prototype/rr2.
