# Данные и правила согласованности

Таблицы SQL используют snake_case. UML имена Service, Window, UserAccount, Ticket, TicketEvent, WindowService, DailyCounter и IdempotencyKey соответствуют service, service_window, user_account, ticket, ticket_event, window_service, daily_counter и idempotency_key.

Ticket.id — UUID, постоянный идентификатор. number — строка префикс-последовательность с минимум тремя цифрами, например A-003. Номер на экране повторяется в разные дни; полная уникальность номера проверяется через услугу, business_date и seq_no. Префикс услуги после выдачи талонов не изменяется.

business_date — календарная дата Europe/Moscow, вычисленная при выдаче. created_at обязателен, called_at, started_at и finished_at заполняются при переходах. timestamptz хранит момент времени; отображение выполняется в рабочей зоне. Сравнение моментов производится в UTC. Создание и события используют часы сервера; синхронизация устройств не даёт клиенту права назначать время записи.

Состояния и команды

| Исходное | Команда | Новое | Дополнительное условие |
| --- | --- | --- | --- |
| нет | issue | waiting | Активная услуга, ключ запроса, счётчик |
| waiting | call_next | called | Свободное окно и допустимая услуга |
| waiting | cancel | cancelled | Право владения либо роль администратора |
| called | repeat_call | called | Окно назначения, called_at сохраняется |
| called | start | in_service | Окно назначения |
| called | mark_no_show | no_show | Не меньше 120 с после вызова |
| in_service | complete | completed | Окно назначения |

Вместе с каждым переходом сохраняется TicketEvent. from_status пуст только при создании. Для repeat_call обе стороны called. События посетителя или терминала имеют actor_user_id NULL, события сотрудников — FK учётной записи. Таблицы событий не дают обычным ролям права удаления. Равные времена упорядочиваются по UUID.

Дополнительные атрибуты подробного DDL, не показанные в сокращённых полях диаграмм: Ticket.version для контроля устаревшей команды, Ticket.owner_token_hash для права отмены, IdempotencyKey.request_hash для обнаружения повторного ключа с иными параметрами. Секрет владения — 32 случайных байта в hex, создаётся клиентом один раз для выдачи, передаётся по TLS и хранится на клиенте отдельно от публичного номера; в БД сохраняется SHA-256, секрет не попадает в журнал.

DailyCounter имеет составной ключ service_id/business_date. IdempotencyKey имеет составной ключ scope/token; scope назначает сервер для терминала или анонимного клиентского сеанса. Повтор одного ключа с тем же телом возвращает прежний Ticket, с иным телом — 409. Для сохранения строгого FIFO не применяется SKIP LOCKED при выборе талона. Операции получают блокировки в согласованном порядке, при взаимной блокировке транзакция откатывается и безопасно повторяется с ограничением числа попыток.

Услуга может быть приостановлена для новой выдачи. Уже выданные waiting продолжают участвовать в выборе. Отключение окна не переносит активный талон без отдельного решения ответственного. Смена дня не удаляет историю; незавершённые вчерашние талоны разбираются до открытия следующей смены.

Среднее ожидание использует completed с started_at, рассчитывается как среднее started_at − created_at. Неявки и отмены не включаются в среднее. Прототип делит разность миллисекунд на 60000 и показывает одну десятичную цифру. При пустой выборке выводится прочерк, а не ноль.
